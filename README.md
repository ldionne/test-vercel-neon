# test-vercel-neon

A hello world guestbook to get acquainted with Next.js, Vercel and Neon.

## Layout

- `app/page.tsx`: the home page. A Server Component that reads messages straight from the database, inside a
  `<Suspense>` boundary so the rest of the page is prerendered and the list streams in per request.
- `app/actions.ts`: Server Actions (`addMessage`, `likeMessage`), server functions called directly from the UI.
- `app/like-button.tsx`: a Client Component (`"use client"`), the only part of the page with client-side state.
- `app/api/messages/route.ts`: a Route Handler serving the messages as JSON at `/api/messages`.
- `db/`: the Drizzle schema and client, using Neon's HTTP driver.
- `drizzle/`: SQL migrations generated by drizzle-kit.

## Development

```sh
npm install
vercel link                 # connect this directory to the Vercel project
vercel env pull .env.local  # fetch DATABASE_URL and friends
npm run db:migrate          # apply migrations to the database in .env.local
npm run dev                 # http://localhost:3000
```

After changing `db/schema.ts`, run `npm run db:generate -- --name <description>` to create a migration.

## Deployment

Vercel deploys `main` to production and every other branch to a preview. Each preview deployment gets its own Neon
branch, a copy-on-write copy of the production database. `vercel.json` runs `npm run db:migrate` before
`next build`, so every deployment migrates the database it is connected to: previews migrate their branch, production
deployments migrate production.
